Wir betreten Schritt drei mit einem ersten Entwurf. Normalisierung prüft ihn gleich. Morgen stellt SQL diesen Tabellen Fragen.
?

Department 1:n Lecturer, wo liegt department_id?

auf der n-Seite: lecturers
Erwartet ist `lecturers.department_id`. Typisch falsch sind eine Lecturer-Liste in departments und zwei gegenseitige Foreign Keys. Ein Lecturer gehört genau einem Department, deshalb trägt er dessen Key.

Entity wird Tabelle

Die Regel ist ein Startpunkt, kein Automatismus. Namen werden plural und snake_case. Identität und Attribute bleiben erhalten.

1:n wird Foreign Key

Der Foreign Key liegt auf der n-Seite. `NOT NULL` setzt die Regel um, dass jeder Lecturer einem Department gehört. Ohne Constraint wäre die Linie nur Dokumentation.

n:m wird Join Table

Join Table (Verknüpfungstabelle) mit Fachlichkeit

Die Join Table zerlegt n:m in zwei 1:n-Beziehungen. Eigene Attribute landen dort. Die eigene ID und der UNIQUE-Constraint schützen zwei verschiedene Formen von Identität.

Weak Entity wird zusammengesetzter Key

Didaktisches Beispiel, nicht im Universitäts-Schema
Die Sitzungsnummer ist nur im Course eindeutig. Der zusammengesetzte Primary Key bewahrt diese Fachregel. Das Repository enthält keine Tabelle `course_sessions`.

Typen und NULL sind Fachentscheidungen

SQLite speichert Datumswerte oft als Text. Wir legen das Format fest. NULL erlauben wir bei einer noch nicht vergebenen Note, nicht aus Bequemlichkeit.

Erster Blick auf CREATE TABLE

CREATE TABLE IF NOT EXISTS courses (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    course_code TEXT NOT NULL UNIQUE,
    title TEXT NOT NULL,
    credits INTEGER NOT NULL CHECK (credits > 0),
    lecturer_id INTEGER NOT NULL,
    FOREIGN KEY (lecturer_id) REFERENCES lecturers(id)
);

Der Tabellenkopf stammt aus der Entity. Constraints setzen Keys und Pflichtfelder um. Der Foreign Key ist die frühere 1:n-Linie.

SQLite braucht den Schalter

SQLite prüft Foreign Keys pro Verbindung nur bei aktivierter Option.
https://sqlite.org/foreignkeys.html
Abruf: 2026-08-23
Ein Constraint im Schema reicht bei SQLite nicht ohne die Verbindungsoption. Das ist ein gutes Beispiel für den Abstand zwischen Diagramm und laufendem System. Als Nächstes prüfen wir, ob unser Schema Wiederholungen und Anomalien enthält.
